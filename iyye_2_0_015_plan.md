# Iyye 2.0.015 — Receiving Email: Implementation Plan

- Status (2026-10-15): **built**; live after a host restart (migration 042), with Iyye's mailbox already configured for sending (plan 0.014). Owner decisions in §4.
- Scope: mail sent to Iyye's own mailbox (`iyye@iyye.tech`, Hostinger) is read, its sender established, and answered by email or deliberately not; trusted senders' mail enters memory.
- Design source: [`iyye_2_0_hld.md`](iyye_2_0_hld.md) §6.2 (scope from the authenticated event), §7.3 (outbox), §9.1–9.2 (surfaces untrusted by default), §15 #3 (isolation), #5 (no false delivery), #15 (forgetting). Builds on plan 0.014 (the mailbox, SMTP, `/person email`) and the Telegram poller's admission pattern (M5).

## 1. Design

- **Reading the mailbox** (`channels/email/imap.ts`, `poller.ts`): the host's own small IMAP client (TLS on 993, certificates verified, AUTHENTICATE PLAIN, SELECT, UID SEARCH, UID FETCH with BODY.PEEK, UID STORE \Seen, IDLE), no dependency. One connection; IDLE between mails (seconds to arrive, a look at least every 10 minutes); every mail after the cursor (`email_cursor`: UIDVALIDITY + last UID) read in order and admitted **in one transaction with the cursor**, then marked seen. Nothing is deleted or moved. First start, or a rebuilt mailbox (UIDVALIDITY changed): only mail arriving from then on. Over 5 MB: headers only, dropped.
- **Parsing** (`channels/email/inbound.ts`): `postal-mime` 4.0.7 (no dependencies, MIT-0) for MIME; the plain part, else the HTML as text; quoted earlier messages cut; at most 20,000 characters; attachments counted, never opened.
- **Who sent it — the receiving server's verdict, never the sender's** (verified on two real mails, Gmail and Outlook, 2026-10-15): only the `Authentication-Results` whose authserv-id is the host the topmost `Received` names (`by fr-int-smtpin35.hostinger.io`), that host the provider's (`authserv` in `config.json`, default `hostinger.io` for Hostinger), and above the second `Received` (where the sender's own headers begin). Genuine when DMARC passed for the From domain or DKIM passed for an aligned domain; SPF alone is not enough. **A mail that is not genuine is never answered** (a forged From would make the reply land on an innocent third party), whoever it claims to be; one claiming a known address tells the owner (≤ 3 a day).
- **Machines are never answered:** `Auto-Submitted`, `List-Id`/`List-Unsubscribe`, `Precedence: bulk`, bounces (`MAILER-DAEMON`, `multipart/report`, empty Return-Path), no-reply addresses (`noreply@`, `do-not-reply@`, `notifications@`…), and mail from Iyye's own address — dropped before any model sees them. Iyye's own replies carry `Auto-Submitted: auto-replied` (RFC 3834), so other machines do not answer them back.
- **Admission** (`admitEmail` in `kernel/admission.ts`; migration 042 rebuilds `events`, `channel_bindings` and `stm_episodes` to allow `email`, and adds the event status `ignored`): the sender is, in order, the person whose address the owner stored (`/person email`); for the owner's own address, the trusted contact `owner-email`, **never the owner** (owner decision 3: no owner principal, no owner memory, never wakes Iyye); the account an earlier mail created (or the person the owner `/link`ed it to); else a new **untrusted contact** bound to the address (owner decision 1: anyone may write). Nothing in a mail links an address or changes trust. A new sender is told to the owner like a new Telegram account (owner decision 1; the same notice, shared cap of 10 a day, with link suggestions). Caps: mail admitted from untrusted senders `IYYE2_EMAIL_UNTRUSTED_DAILY_MAX` (20) a day in all and `IYYE2_EMAIL_SENDER_DAILY_MAX` (5) per sender; trusted senders `IYYE2_EMAIL_TRUSTED_SENDER_DAILY_MAX` (50) each. Every mail read gets an `email_inbox` row with what was decided.
- **Answering** (`channels/email/responder.ts`, the scheduler's mail path; since plan 0.016 not for a trusted sender's mail from an owner-stored address, which is a turn with their chat's tools): one direct completion (thinking off, 2048 tokens, cut off = failure) on the Telegram model with Iyye's identity, the same scoped recall as the sender's chats, and the mail quoted as data. **No Pi session and no tools for anyone** (owner decision 3: a mail never makes Iyye act). Trusted senders are always answered (a `NO_REPLY` is asked again); everyone else may get `NO_REPLY` (owner decision 2), which settles the job and marks the event `ignored`. A reply goes through the outbox to the sender's address, `Re:` the subject, threaded (`In-Reply-To`, `References`, sanitized ids).
- **Order:** mail from a trusted sender is ordered like their chats; mail from anyone else waits behind every conversation and never ages ahead (owner decision 2: trusted contacts first). Mail never wakes Iyye.
- **Memory:** only trusted senders' answered mail enters short-term memory (`recordEpisode`; owner decision 3), and the night names it as email.
- **Failures** never mail an apology: a stranger's failure, including a reply that bounces, is only recorded (job settled, event `ignored`), so a stranger's mail never raises a motivation (the motivations' detectors read only short-term memory, which strangers' mail never enters, and failed jobs); a trusted sender's is a failed job like any conversation's.
- **Owner view:** `/email` (the latest mails, sender and trust, subject, verdict, the reply's state, unverified senders, the poller's state); the day summary counts mail received by outcome; the web chat's attention list shows a reply that failed.
- **`/forget <person>`:** their mail's words, subject, sender address and thread ids go from the events, the replies' routes, and `email_inbox` (also mail from their addresses dropped before admission); their stored address is deleted. The copy in the mailbox itself is not touched (a known limit).

## 2. Risks

- **Spam volume:** filtered machines and unverified senders cost nothing; the caps bound model time and new contacts. Hostinger's own spam folder (`INBOX.Junk`) is never read.
- **A provider without usable `Authentication-Results`** (or a changed format): nothing is verified, so nothing is admitted — fails closed. The real smoke shows the verdict per mail.
- **Prompt injection by mail:** the mail is quoted data, the model has no tools, and the reply goes only to the verified sender.
- **The owner's mail is not the owner:** a stolen mailbox of the owner yields a trusted contact's reach, not the owner's.

## 3. Tests

`host/test/email-inbound.test.ts`: parsing and forged results, admission and caps, the mail path through the scheduler and the outbox (fake SMTP), memory, order, failures, `/email`, the day line, `/forget`, and the poller and client against `host/test/fixtures/fake-imap.ts`. Never a real mailbox from tests. `host/scripts/email-inbound-smoke.ts` is the owner's read-only real smoke (verified 2026-10-15 against the real mailbox: both test mails verified, the welcome mail not).

## 4. Owner decisions (2026-10-15)

1. Anyone may write; unknown senders become untrusted contacts.
2. Iyye decides whether to reply, from the text and the sender; trusted contacts first and always answered.
3. The owner's own address does not authenticate as the owner (unlike a linked Telegram account): no actions; replies, and short-term memory for trusted senders only. Amended 2026-10-16 (plan 0.016): a trusted sender's mail from an address the owner stored gets that person's chat tools; the owner's address is still only the trusted contact `owner-email`.
4. Dependencies only if required (one: `postal-mime`).
